# Crowd Simulation Engine

A backend simulation engine for **pre-event stampede risk analysis**. This module simulates crowd flow, congestion, and potential instability conditions in venues defined by YAML files.

## Overview

This simulation engine:
- Loads venue layouts from YAML files (generated by the venue editor)
- Constructs a navigable path graph from roads/pathways and joints
- Spawns agents at entry points and moves them toward exits
- Models crowd dynamics including congestion, stop-go waves, and density effects
- Provides tunable parameters to create stress-test scenarios
- Outputs metrics for risk analysis and visualization

## Usage

### Command Line

```bash
# Basic simulation
python -m crowd_simulation path/to/venue.yaml

# With scenario preset
python -m crowd_simulation venue.yaml --scenario high_density

# Custom parameters
python -m crowd_simulation venue.yaml --spawn-rate 3.0 --duration 1800

# Export results
python -m crowd_simulation venue.yaml --output results.json --csv metrics.csv

# Stress test with surge event
python -m crowd_simulation venue.yaml --scenario stress_test --surge --surge-time 60
```

### Python API

```python
from crowd_simulation import CrowdSimulation, Venue, SimulationConfig
from crowd_simulation.config import ScenarioPresets
from crowd_simulation.output import RiskReport, JSONExporter

# Load venue
venue = Venue.from_yaml('venue.yaml')

# Create configuration
config = ScenarioPresets.high_density()
# Or customize:
config = SimulationConfig(
    spawn_rate_multiplier=3.0,
    max_simulation_time=1800.0,
    surge_enabled=True,
    surge_start_time=300.0,
    surge_multiplier=5.0
)

# Run simulation
sim = CrowdSimulation(venue, config)

# With callback for real-time monitoring
def on_update(state):
    print(f"Time: {state.timestamp:.1f}s, Agents: {state.metrics.total_agents}")

results = sim.run(callback=on_update, metrics_interval=1.0)

# Generate risk report
report = RiskReport.generate(results)
print(f"Risk Level: {report['risk_level']}")

# Export results
JSONExporter.export_results(results, 'results.json')
```

### Generator-based execution (for integration)

```python
sim = CrowdSimulation(venue, config)

for state in sim.run_generator(metrics_interval=1.0):
    # Process each state
    positions = sim.get_agent_positions()
    # Send to visualization, etc.
```

## Configuration Parameters

### Time Control
- `timestep`: Simulation timestep (default: 0.1s)
- `max_simulation_time`: Maximum duration (default: 3600s)

### Spawn Control
- `spawn_rate_multiplier`: Global spawn rate multiplier (default: 1.0)
- `initial_spawn_burst`: Agents to spawn at t=0 (default: 0)

### Agent Properties
- `preferred_speed_mean`: Average walking speed (default: 1.4 m/s)
- `preferred_speed_std`: Speed variation (default: 0.3 m/s)

### Density & Congestion
- `max_density_per_meter`: Maximum density (default: 6.0 agents/m)
- `comfortable_density`: Free-flow density (default: 2.0 agents/m)
- `critical_density`: Unstable flow density (default: 5.0 agents/m)
- `congestion_exponent`: Speed reduction aggressiveness (default: 2.0)

### Surge Events
- `surge_enabled`: Enable surge events (default: False)
- `surge_start_time`: When surge begins (default: 300s)
- `surge_duration`: Surge duration (default: 60s)
- `surge_multiplier`: Spawn rate during surge (default: 5.0)

### Exit Control
- `exit_capacity`: Agents/second per exit (default: 2.0)
- `blocked_exits`: List of blocked exit IDs
- `partial_exit_capacity`: Dict of exit ID to capacity fraction

## Scenario Presets

| Preset | Description |
|--------|-------------|
| `normal_flow` | Standard steady-state operation |
| `high_density` | 3x spawn rate for crowded conditions |
| `sudden_surge` | Simulates event ending with crowd surge |
| `near_stampede` | High density + surge + reduced exit capacity |
| `stress_test` | Maximum stress: 6x spawn, burst, reduced exits |

## Crowd Dynamics Model

The simulation uses a **fundamental diagram** approach:

```
v = v_free × (1 - (ρ/ρ_max)^n)
```

Where:
- `v_free` = preferred speed
- `ρ` = local density
- `ρ_max` = jam density
- `n` = congestion exponent

Additional effects:
- **Choke point slowdown**: Speed reduction near bottlenecks
- **Stop-go waves**: Backward-propagating density waves
- **Reaction time**: Delayed speed adjustments for realism

## YAML Venue Format

The simulation expects venues in this format:

```yaml
pixelsPerMeter: 50  # For indoor venues
type: indoor  # or outdoor

pathways:
  - id: 1
    name: Main Corridor
    width: 3
    points:
      - {x: 100, y: 100}
      - {x: 500, y: 100}
      - {x: 500, y: 400}

entries:
  - id: 10
    name: Main Entrance
    x: 100
    y: 100
    spawnRate: 2

exits:
  - id: 20
    name: Emergency Exit
    x: 500
    y: 400
    exitRate: 3

chokePoints:
  - id: 30
    name: Narrow Section
    x: 300
    y: 100

joints:
  - id: 40
    name: T-Junction
    x: 500
    y: 100
    connectedPathways: [1, 2]
```

## Exit Codes

- `0`: LOW risk
- `1`: MODERATE risk  
- `2`: HIGH risk
- `3`: CRITICAL risk
